# AnythingLLM

Full-stack app (v1.8.2) for chatting with private documents using configurable LLMs, embedders and vector DBs. Yarn monorepo, Node >=18 (`.nvmrc` 18.18.0). The server is CommonJS; the root `package.json` is `"type": "module"`.

## Layout
- `server/` — Express API. `endpoints/`, `models/` (Prisma-backed model classes), `utils/` (`AiProviders/`, `EmbeddingEngines/`, `vectorDbProviders/`, `agents/`, `MCP/`, `chats/`, `helpers/`), `prisma/` (schema, migrations, `seed.js`), `swagger/`, `__tests__/`.
- `frontend/` — Vite + React app; i18n files in `frontend/src/locales/<lang>/`.
- `collector/` — separate service that parses uploaded files, links and raw text (`processSingleFile`, `processLink`, `processRawText`, `extensions`).
- `docker/` — Dockerfile, compose, `.env.example`. Also `embed/` and `browser-extension/` (git submodules), `cloud-deployments/`.

## Setup and run (from repo root)
- `yarn setup` installs all three packages, copies the `.env.example` files (server uses `server/.env.development`) and runs Prisma generate/migrate/seed.
- Run each in its own terminal: `yarn dev:server`, `yarn dev:collector`, `yarn dev:frontend` (or `yarn dev:all`).
- Prisma: `yarn prisma:generate`, `yarn prisma:migrate`, `yarn prisma:seed`, `yarn prisma:reset`. Schema changes need a new migration in `server/prisma/migrations`.

## Tests and lint
- Tests: `yarn test` (Jest, run from root). The only existing tests are under `server/__tests__/` (`*.test.js`).
- Lint: `yarn lint` from root. It runs Prettier with `--write` in server, frontend and collector, so it modifies files. Prettier config is `.prettierrc` (2 spaces, double quotes, semicolons, width 80, trailing commas es5).
- Translations: `yarn verify:translations` (CI `check-translations.yaml` runs it). After editing `frontend/src/locales/en`, run `yarn normalize:translations`; keep other locales in sync.

## Generated files and pitfalls
- `server/swagger/openapi.json` is generated by `cd server && yarn swagger` (swagger-autogen via `swagger/init.js`) from the developer API endpoints in `server/endpoints/api/`. Do not hand-edit it; regenerate after changing those endpoints.
- AWS/GCP deployment templates are generated with `yarn generate:cloudformation` and `yarn generate::gcp_deployment` (note the double colon). Don't edit the outputs by hand.
- Per-package `.env` files are git-ignored; add new settings to the matching `.env.example` (and `server/utils/helpers/updateENV.js` if they are user-configurable).
- Adding an LLM/embedder/vector DB provider touches several places: the provider class under `server/utils/`, the selector helper in `server/utils/helpers/index.js`, `updateENV.js`, and the frontend settings pages.
