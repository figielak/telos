# Roadmap
<!-- Telos building itself; .planning/ uses the .telos/ format and moves there in phase 03.
     Goals and criteria from SPEC §14. -->
- 01-skeleton [done] plugin, CLI skeleton (ctx, status), config, templates, init · done when: `/telos:init` works in a test repo
- 02-core-loop [done] plan, approve, revise, do, quick, status, accept, lint-plan, roadmap set, SessionStart hook, git guard · done when: a minimal phase runs end to end with commits
- 03-map [done] map-scan, map, incremental refresh, PROJECT draft · done when: MAP.md for a real Astro and a real Python repo under limits
- 04-standard [done] discuss, CONTEXT, check, done, undo, lesson, profile switching, std hooks · done when: standard phase incl. undo works
- 05-deep [done] reviewer, researcher, research, review, critical/TDD/e2e, docs, ADR, retro · done when: deep phase incl. doc-sync works
- 06-measure [done] budget measurements on 2–3 real repos, trim templates and prompts · done when: targets in SPEC §12 met or documented
- 07-benchmark [done] Public, pre-registered A/B/C benchmark of Telos vs bare Claude Code and a hand-written CLAUDE.md on real repositories · done when: bench/RESULTS.md reports every pre-registered cell (5 reps × variants A/B/C) with raw data under bench/results/, and npm test passes
- 08-website [done] Public landing page for Telos in website/ built with Astro and Tailwind CSS, Ancient Precision direction, stating only verifiable facts · done when: npm --prefix website ci && npm --prefix website test exits 0; website/DESIGN.md exists; root npm test passes with root package.json unchanged; no horizontal scroll at 390, 768 and 1440 px
- 09-command-guide [dropped] Website guide explaining every Telos skill and CLI command, when to use it, examples and complete workflows · done when: Every current skill and CLI command has a linked guide entry; five workflows show prerequisites and outcomes; npm --prefix website test and npm test pass; guide works at 390, 768 and 1440 px
- 10-prune [done] Cut Telos to a memory core: skills status, plan, close, map; SessionStart hook and git guard; remove profiles, -lite/-hard variants, separate gates, ADR, docs-scan, changelog, undo, agents and website/; rewrite PROJECT Purpose and Out of scope · done when: skills/ has at most 4 directories; config.json has no profile key; README.md has at most 200 lines; every removed path is in HISTORY Delete-zone; npm test passes
- 11-areas [planned] Two-level memory: MAP.md becomes an index (about 600 tokens) and each area gets .telos/areas/<name>.md (about 800 tokens) with fixed sections: purpose, invariants, decisions and reasons, rejected approaches, pitfalls, entry points · done when: telos area new, list and show work; lint enforces limits and sections; a task bundle loads only the areas matching its paths; npm test passes
- 12-anchors [planned] Staleness detection: each area header records a commit and the paths it covers; telos stale reports areas whose paths changed since the anchor and references to missing files; SessionStart shows the stale count · done when: fixture tests detect a changed covered file and a deleted reference without any model call; npm test passes
- 13-close-catchup [planned] One write point for memory: /telos:close updates STATUS, touched areas, HISTORY and anchors; /telos:catchup does the same from git log <anchor>..HEAD for work done outside Telos; one mechanism, two entries · done when: an e2e test with commits made without Telos yields a bundle of at most 6000 chars listing the changed areas, and telos stale is empty after the run; npm test passes
- 14-agents [planned] Agent-agnostic use with Codex: telos init writes the rules block to AGENTS.md and CLAUDE.md imports it; the CLI prints each command's instructions via telos ctx so any agent can run it; first task verifies how Codex currently defines custom commands · done when: the same plan, work, close run passes on a test repository in Claude Code and in Codex, recorded as a live smoke run; correctness depends on no hook; npm test passes
- 15-resume-test [planned] Memory acceptance test: a file of 5 to 10 questions with key answer facts (what is next, where X lives, why Y) and a script that runs a fresh headless session with and without memory; the script must not live under bench (Delete-zone) · done when: one command prints correct/total and cost for both variants; npm test passes
- 16-dogfood [planned] Real-project trial and go/no-go: two to three weeks of work on the large project, at least one week of pause, then the resume test · done when: the post-pause resume-test result and the overhead of status, close and catchup sessions against the total are recorded; over 15% overhead or no advantage over no memory closes the project
